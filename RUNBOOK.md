# Daily refresh runbook (for the scheduled agent)

Goal: rebuild `B2B_Dashboard.html` with data from **2026-10-31 through today**, send it to the user with SendUserFile (display "render"), and commit a metrics-only snapshot (no leads) to `data/history/YYYY-MM-DD.json`.
Timezone for "today": America/Phoenix. All Klaviyo model calls need `model="claude-sonnet-5-5"` (or your model). Read-only on Klaviyo and BigQuery; never create/update/delete anything there.

Follow the ecom-metrics dictionary skill if available: samples excluded (`order_type='Order'`), net sales from net_sales_bookings, units/orders/cost from order_items, margin = PRODUCT margin using `estimated_cost_usd` (invoice `cost_usd` is sparsely populated), US only (Shopify datasource for order-name joins).

Step A (Klaviyo): `ask_analytics_question` (K-SQL) asking for Shopify Placed Order events (`klaviyo.events.shopify.Order`) from 2026-10-31 UTC to tomorrow, one row per order, with columns order_name (`extra.name`), order_value, discount_codes, and 0/1 flags in_core_list, in_core_segment, got_flow_email, submitted_form, used_coupon, in_extended; only orders with any flag. Ask for ONE ROW PER ORDER (order_name, flag_string) up to 1000 rows. K-SQL does NOT support STRING_AGG, so aggregated name lists fail; plain rows work (about 190 rows). After each K-SQL call, READ the SQL it returns and verify every list/segment/flow/form ID is exactly as given in this runbook: the tool is LLM-written and has mistyped an ID before (SZMWtA became SZWtA once). Known behavior: list/segment tables are `klaviyo.relations.list_memberships` / `segment_memberships` (current membership); flow emails `klaviyo.events.received_emails` (data.$flow); forms `klaviyo.events.api.\`Form submitted by profile\`` (data.form_id); orders join on `profile_internal_id`. Note the K-SQL tool times out at 60s: keep queries simple; run pieces separately if needed.
Encode each order as `<order_name><flags>` with letters l=list s=segment f=flow-email m=form c=coupon x=extended, e.g. `US126391lfmx`.

Step B (BigQuery): join those order names to BigQuery. Template:
```sql
WITH raw AS (SELECT x FROM UNNEST(SPLIT('<space-separated encoded orders>', ' ')) x),
c AS (SELECT SUBSTR(x,1,8) order_name, SUBSTR(x,9) fl FROM raw WHERE x != ''),   -- adjust SUBSTR if order names are longer than 8 chars
shop AS (SELECT order_name, MIN(order_created_at) d, SUM(net_revenue_usd) oi_net, SUM(estimated_cost_usd) est_cost FROM `hd-global-analytics-platform.mart_ecom_tracker.order_items` WHERE country='US' AND order_type='Order' AND DataSource='Shopify' AND order_created_at BETWEEN '2026-10-31' AND CURRENT_DATE() GROUP BY 1),
nbs AS (SELECT order_name, SUM(net_sales_usd) net_sales FROM `hd-global-analytics-platform.mart_ecom_tracker.net_sales_bookings` WHERE country='US' AND date_ref BETWEEN '2026-10-31' AND CURRENT_DATE() GROUP BY 1),
big AS (SELECT order_name FROM nbs WHERE net_sales >= 3000 AND order_name IN (SELECT order_name FROM shop)),
ca AS (SELECT b.order_name, IFNULL(c.fl,'') fl, TRUE is_big FROM big b LEFT JOIN c ON c.order_name=b.order_name),
c2 AS (SELECT order_name, TRUE core, REGEXP_CONTAINS(fl,r'l') f_list, REGEXP_CONTAINS(fl,r's') f_seg, REGEXP_CONTAINS(fl,r'f') f_flow, REGEXP_CONTAINS(fl,r'm') f_form, REGEXP_CONTAINS(fl,r'c') f_coupon, is_big f_big, (is_big AND NOT REGEXP_CONTAINS(fl,r'[lsfmc]')) big_only FROM ca)
SELECT FORMAT_DATE('%Y-%m-%d', DATE(shop.d)) d, 'core' tier, COUNT(*) orders, ROUND(SUM(nbs.net_sales),2) net_sales, ROUND(SUM(shop.est_cost),2) est_cost,
 COUNTIF(f_list) n_list, COUNTIF(f_seg) n_seg, COUNTIF(f_flow) n_flow, COUNTIF(f_form) n_form, COUNTIF(f_coupon) n_coupon,
 ROUND(SUM(IF(f_list,nbs.net_sales,0)),2) s_list, ROUND(SUM(IF(f_seg,nbs.net_sales,0)),2) s_seg, ROUND(SUM(IF(f_flow,nbs.net_sales,0)),2) s_flow, ROUND(SUM(IF(f_form,nbs.net_sales,0)),2) s_form, ROUND(SUM(IF(f_coupon,nbs.net_sales,0)),2) s_coupon,
 COUNTIF(f_big) n_big, ROUND(SUM(IF(f_big,nbs.net_sales,0)),2) s_big, COUNTIF(big_only) n_bigonly, ROUND(SUM(IF(big_only,nbs.net_sales,0)),2) s_bigonly
FROM c2 JOIN shop USING(order_name) LEFT JOIN nbs USING(order_name) GROUP BY 1,2 ORDER BY 1,2
```
Fill `cohort[]` (one per day, same order as `D.top`): `{d:'MM-DD', core:{o,net,cost,nl,ns,nf,nm,nc,sl,ss,sf,sm,sc,nb,sb,nbo,sbo}, ext:{o,net,cost}}`. `nb/sb` must equal all core orders/sales because all meet $3,000; `nbo/sbo` are threshold orders with no other core signal. Keep `ext` zero for schema compatibility and zero-fill days with none.

Largest single B2B orders (`D.big`, PII: emails and names, never commit): run the same CTEs as Step B but END with this SELECT (the `shop` CTE must also carry `ANY_VALUE(LOWER(TRIM(email))) email, ANY_VALUE(first_name) fn, ANY_VALUE(last_name) ln, ANY_VALUE(shipping_address_city) city, ANY_VALUE(shipping_address_province) st, SUM(line_item_quantity) units, ARRAY_TO_STRING(ARRAY_AGG(DISTINCT product_name IGNORE NULLS LIMIT 2), ' | ') prods`):
`SELECT ca.order_name, FORMAT_DATE('%Y-%m-%d', DATE(shop.d)) d, ROUND(nbs.net_sales,2) net, shop.units, shop.email, shop.fn, shop.ln, shop.city, shop.st, shop.prods, CONCAT(REGEXP_REPLACE(ca.fl,'x',''), 'b') sig, REPEAT('x',500) pad FROM ca JOIN shop USING(order_name) JOIN nbs USING(order_name) WHERE nbs.net_sales >= 3000 ORDER BY nbs.net_sales DESC LIMIT 400`
The `pad` column is deliberate: it makes the tool save the result to a file instead of echoing 200+ rows into context. Parse that file with python and build `D.big = [{o,d,net,units,em,fn,ln,city,st,prods,sig}]` (sig letters: l list, s segment, f flow email, m form, c coupon, b large order). In `data/history/*.json` set `D.big` to `[]`.

US totals per day -> `D.top[]` (alias the order_items columns distinctly, e.g. `oi.oi_net`, `oi.est_cost`, to avoid nested-record output) {d:'YYYY-MM-DD', net (net_sales_bookings net_sales_usd), gross (gross_sales_usd), orders (distinct order key: order_name if Shopify else order_id, order_type='Order', is_original_version IS NULL OR =1), oi (order_items SUM(net_revenue_usd)), cost (SUM(estimated_cost_usd))}.
Disclose in the dashboard text: samples excluded; net sales = total net revenue incl. shipping/other charges; cost = PRODUCT cost only, estimated cost covers only about a third of lines.
